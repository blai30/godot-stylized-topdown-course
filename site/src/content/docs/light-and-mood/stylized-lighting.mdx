## What you will build

The last piece of the look: surfaces that answer to the light in a soft, hand-painted way. The side of a rock that faces away from the sun stays softly lit instead of going dark, and a faint rim along its edge, tinted by the time of day, separates it from the ground behind it.

## The idea

Godot lights a surface with a formula for every light. The default formula, **diffuse**, is the dot product of the surface's normal and the direction to the light, written `N · L`. It is 1 where the surface faces the light, 0 where it is edge-on, and below 0, which counts as 0, where it faces away. The line where the light reaches 0 is the **terminator**, and on a rock it is a hard edge between a bright side and a dark side.

Painted art does not do that. Shadows in a painting are colored and soft, and nothing is black. **Wrapped diffuse** moves the formula over: `(N · L + 0.5) / 1.5` is 1 where the surface faces the light, still 0.33 where it is edge-on, and reaches 0 only at `N · L = -0.5`, well past edge-on. The terminator becomes a wide gradient.

A **rim** is a faint light along the silhouette, where the surface turns away from the camera. It separates a rock from the ground at its foot, and from its own shadow.

Both go into one **shader include**: a `.gdshaderinc` file of shared code that any shader can paste in with `#include`, so the ground, the rocks, and later the trees all light the same way. The rim's color and strength come from two **shader globals**: values set once, for the whole project, that every shader can read. The day animation keys them, so dusk gets a warm rim and night a cool one.

	<Figure

</Steps>

Type into the new file so that:

- a comment on the first line says it is the lighting shared by the template's stylized surfaces: wrapped diffuse light and a soft rim. An include has no `shader_type`: it takes the type of the shader that includes it;
- `global uniform vec4 rim_color : source_color;` and `global uniform float rim_strength;` read the globals, with a comment: the rim's color and strength, which `DayClock` sets from the day animation. A color global is a `vec4` in a shader, and you use its `.rgb`;
- `const float WRAP = 0.5;` has a comment: how far the light wraps around a surface, where 0 is plain diffuse and 1 reaches the far side;
- `const float RIM_POWER = 3.0;` has a comment: how narrow the rim is, where a higher power keeps it closer to the silhouette;
- a function `vec3 soft_rim(vec3 view_normal, mat4 inverse_view)` has a comment: a faint glow along the silhouette that separates a surface from the ground behind it. In it, `float edge = pow(1.0 - clamp(view_normal.z, 0.0, 1.0), RIM_POWER);` is 0 where a surface faces the camera and 1 at the silhouette. The comment above says the camera looks along -Z in view space, so a normal turned away from +Z is near the silhouette;
- then `float world_up = (inverse_view * vec4(view_normal, 0.0)).y;` turns the normal back into world space, to read how far it faces up, and `float sky = clamp(0.5 + world_up, 0.0, 1.0);` is 1 for faces looking up, a half for upright faces, and 0 for faces looking down, so the underside of a rock never glows. The comment says that;
- the function returns `rim_color.rgb * rim_strength * edge * sky`;
- `void light()` is Godot's per-light function. A comment says plain diffuse is the dot product alone, and wrapping shifts it so the side facing away from the light stays softly lit. It computes `float wrapped = clamp((dot(NORMAL, LIGHT) + WRAP) / (1.0 + WRAP), 0.0, 1.0);` and adds `wrapped * ATTENUATION * LIGHT_COLOR / PI` to `DIFFUSE_LIGHT`. `ATTENUATION` carries the shadow, so a cast shadow is still dark.

<Aside type="note" title="Why the rim uses the view-space normal">
Under a perspective camera, Godot gives a shader `VIEW`, the direction to the camera. Under the orthographic camera every ray is parallel, so a `VIEW` that points at one spot would slide the rim across the screen. FactoryGame found the same and uses the view axis instead. In view space the camera looks along -Z everywhere, so the view-space normal's `z` is the answer on both kinds of camera.
</Aside>

The `.glb` files keep their material, `palette.tres`. A **Material Override** on the mesh in the inherited scene replaces it for every instance of that rock, and leaves the imported file and the original material alone, so you can switch back by clearing the override.

<Aside type="note" title="What the custom light function gives up">
A `light()` function replaces Godot's default lighting for that surface, including the shiny highlight, so these surfaces are matte: roughness has no effect on them. That suits ground and rocks. A glossy material, such as water or a metal machine, would add its own specular term in `light()`.
</Aside>

## Try it

- Raise `WRAP` to `1.0` in the include and run: the shadow side gets even lighter, flatter, and softer. Put it back.
- Set `RIM_POWER` to `1.0`: the rim widens into a glow. At `8.0` it nearly disappears.
- In the `Looks` table of `BuildDay`, change the noon rim strength (`0.50`) from `0.30` to `1.0`, run `BuildDay` again, hold the day at `0.5`, and run: the rim shows plainly on every rock. Then put it back. The day animation sets the rim on every seek, so a value typed into **Rim Strength** by hand would be overwritten.

## If it does not work

- **The shader reports that `rim_color` must be a `vec4`.** A color global is a `vec4`. Declare it as `global uniform vec4 rim_color : source_color;` and use `.rgb`.
- **The shader says it cannot find the global.** The globals are missing, or their names differ. Check **Project Settings > Globals > Shader Globals**.
- **The rocks are white or have no texture.** The material's **Palette** is empty. Quick-load `palette.png` into it.
- **There is no rim.** `rim_strength` is 0 until the clock sets it. Check that `Day` has the `DayClock` script, that the project is built, and that **Rim Strength** is above 0 at the hour you look at.
- **Only some rocks changed.** Each rock scene needs the override. Do `rock_large.tscn` too.
- **The ground looks the same.** The include was added to the shader but the shader did not save. Save it with <Kbd keys="Ctrl+Alt+S" mac="Cmd+Option+S" />.
