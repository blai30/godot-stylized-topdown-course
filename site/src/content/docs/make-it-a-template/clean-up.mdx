## What you will build

A project that is tidy enough to copy. The `art` folder becomes a library: models, materials, shaders, and textures, with no scripts in it and no path that leads outside it. You write a small audit that proves it, fix what the audit finds, write the two READMEs a newcomer reads first, and make the build refuse code that breaks the style.

Nothing changes on screen. The meadow looks exactly as it did, and you check that.

<Aside type="note" title="Why the art folder is a library">
A game's art outlives the game. If `art` refers only to itself, you can copy it into the next game, share it between games, or keep it in a repository of its own. The two rules are short: **no scripts** and **no reference to anything outside the folder**. Scripts and scenes that use the art live beside it, in `src`, `world`, and `levels`.
</Aside>

## Write the audit

You find what breaks the rules by asking a script, not by looking. The audit is an editor script, like the one that keyframed the day in lesson 21: you run it from the Script editor, and it prints to the Output panel. It reads every file in the project once.

<Steps>

1. In your code editor, create the folder `tools` at the project's root, beside `art`, and in it a file named `audit_project.gd`. Save the code below into it. It is GDScript, the language Godot's editor scripts are usually written in; you do not need to learn it, only to read what it checks.

2. In Godot, double-click `tools/audit_project.gd` in the FileSystem dock to open it in the Script editor.

3. Choose **File > Run** in the Script editor. The Output panel lists the problems.

</Steps>

The script does four things:

- It collects every file under `res://`, skipping Godot's cache (`.godot`), build output, and `art_source`, which holds files other programs made.
- For each file under `art/`, it reports any `.cs` or `.gd` file, and, in scenes, resources, and shaders, any `res://` path that does not start with `res://art/` and any use of a script.
- For every file, it checks its name: outside `src`, `snake_case`; inside `src`, `PascalCase` for folders and files. A `.uid` or `.import` file is named after its source, and a `README.md` is named for what it is.
- It prints each problem on a line of its own and a count, and says `0 problems` when the project is clean.

## Let the shader place the tree in the wind

`WindPhase` gave each tree its own place in the wind: it computed a number from the tree's position and handed it to the tree's meshes as the `tree_phase` instance uniform. But the shaders already know where each tree stands: `tree_origin` is the position of the object that is being drawn. A shader can compute the same number itself, with no script and no uniform to set.

<Steps>

1. In `art/shaders/wind.gdshaderinc`, add a function above `tree_sway`: `tree_phase_at(vec3 tree_origin)`, which returns `fract(tree_origin.x * 0.37 + tree_origin.z * 0.61)`. These are the numbers `WindPhase` used. `fract` keeps the part after the decimal point, so the result is always from 0 up to 1, like `PosMod(..., 1)` did.

2. In `art/shaders/bark.gdshader`, delete the `tree_phase` instance uniform and its comment. In `vertex`, pass `tree_phase_at(tree_origin)` where `tree_phase` was passed to `tree_sway`.

3. In `art/shaders/foliage.gdshader`, delete the `tree_phase` instance uniform and its comment. In `vertex`, add `float tree_phase = tree_phase_at(tree_origin);` under the line that sets `tree_origin`. The two lines that use `tree_phase` stay as they are.

4. Save all three files.

</Steps>

## Give the player the animation script

`PlayerAnimation` blends the character's walk and run clips by how fast the body is moving. It sits on the `AnimationTree` inside `character.tscn`, which is art. The script is not art, it is the game's behavior, so it moves to the scene that owns the body: the player.

<Steps>

1. Open `art/character/character.tscn` and select the `AnimationTree` node. Under **Script**, click the arrow and choose **Clear**. Save.

2. Open `world/player/player.tscn`. A scene you instanced shows only its root. To change a node inside it, right-click `character` in the Scene dock and choose **Editable Children**. The instance opens, and its nodes appear below it.

3. Select `character/AnimationTree`. Click **Script**'s empty field, choose **Quick Load...**, type `PlayerAnimation`, and press <Kbd keys="Enter" />.

## Move the tile set to the world

The tile set is a resource made from the `GroundTileSet` and `GroundTile` classes: it lists which tiles exist and how fast the player walks on each. It belongs to the game, and it only points at art, the meshes in `ground_tiles.meshlib`. So it belongs outside `art`.

<Steps>

1. In the FileSystem dock, right-click the `world` folder and choose **Create New > Folder...**. Name it `ground` and click **OK**.

2. Drag `art/ground/ground_tile_set.tres` onto `world/ground`. Godot moves the file and rewrites the scenes that use it, `meadow.tscn` and `generated.tscn`, so nothing breaks.

## Rename the vendor file

Every other file follows the `snake_case` rule. The animation pack's file kept the name its author gave it, `UAL1_Standard.glb`.

<Steps>

1. In the FileSystem dock, click `art/animations/UAL1_Standard.glb`, press <Kbd keys="F2" />, type `ual1_standard.glb`, and press <Kbd keys="Enter" />. Godot renames the file and its import settings, and fixes `character.tscn`, which names it.

2. Keep the credit with the file. In `art/animations`, create a `README.md` if you do not have one, or edit yours. It should name the pack (Quaternius's Universal Animation Library, Standard, CC0), say where it came from, and say that `ual1_standard.glb` was renamed from the pack's `UAL1_Standard.glb`.

</Steps>

## Make the build enforce the style

In lesson 58 you wrote the style rules in `.editorconfig` and turned warnings into errors. By default those rules reach only your code editor. One more line makes the build itself check them, so a script that breaks the style does not compile.

<Steps>

1. In `TopDownTemplate.csproj`, add `<EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>` inside the `<PropertyGroup>`, above `<TreatWarningsAsErrors>`.

2. Save, then click **Build Project**. The build succeeds: every script already follows the rules.

</Steps>

## If it does not work

- **The audit does nothing.** The script is not open in the Script editor, or it is a different file. **File > Run** runs the script that is open and is gray for a script that does not extend `EditorScript`.
- **The audit still lists a `res://src` path in a scene.** The scene was not saved after you cleared its script, or a second scene, such as a copy of the oak, still has it.
- **The trees all sway in step.** The foliage shader still reads the removed `tree_phase` uniform, or `tree_phase_at` is not called in `vertex`. The Output panel shows a shader error if so.
- **The character stands still while the player walks.** `PlayerAnimation` is not on `character/AnimationTree` in `player.tscn`, or **Editable Children** was turned off. Check the **Script** row of that node.
- **The tile set is missing from `GroundTiles` after the move.** The file was moved outside Godot, so the scenes were not rewritten. Set **Tiles** on `GroundTiles` to the file in `world/ground` by hand.
- **The build fails after you add the line.** A script breaks a rule in `.editorconfig`. The **MSBuild** panel names the rule and the line.
