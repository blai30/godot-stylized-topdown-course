## How the camera sees

A normal camera, like your eyes, shows far things smaller than near things. That is a **perspective** projection. Top-down games such as FactoryGame use an [orthographic projection](/reference/glossary/#orthographic-projection) instead: every object shows at the same size wherever it is on screen, and parallel lines stay parallel. A tile at the top of the screen looks exactly like a tile at the bottom, which keeps a tiled world tidy and easy to read.

An orthographic camera has no zoom by distance. Moving it closer changes nothing; what it shows is set by its **Size**, the height of the view in meters. Size 20 shows 20 meters of the world from the bottom of the window to the top.

The camera looks down at 55 degrees. Straight down would show only the tops of things, flat as a map; 55 degrees shows the fronts of trees, rocks, and characters too, so they read as objects.

## Build the rig scene

The rig is its own scene, so every level can use the same camera. It has three nodes:

- `CameraRig`, the root, is the point the camera looks at. In lesson 6 it moves with the player.
- `Pivot`, under it, tilts everything below it by 55 degrees.
- `Camera3D`, under the pivot, sits 60 meters back along the tilt and looks at the rig's point.

<Steps>

1. In the FileSystem dock, right-click `world` and choose **Create New > Folder...**, as you did for the top folders in lesson 2. Name it `camera` and click **OK**. Then right-click `src` and make a folder named `Camera`, with a capital C, for the rig's code.

2. Open **Scene > New Scene**. A new empty scene opens in its own tab.

3. Click **3D Scene** and rename the root `CameraRig`.

4. With `CameraRig` selected, add a `Node3D` and rename it `Pivot`. Set its **Transform > Rotation** **x** to `-55`.

5. Select `Pivot` and add a `Camera3D` under it. Keep its name, `Camera3D`.

6. With `Camera3D` selected, set in the Inspector:
	- **Transform > Position** **z** to `60`
	- **Projection** to **Orthogonal**
	- **Size** to `20`

7. Save the scene with <Kbd keys="Ctrl+S" mac="Cmd+S" />. The dialog opens at `res://` and proposes `camera_rig.tscn`. Double-click the `world` folder, then `camera`, so the **Path** reads `res://world/camera`, and click **Save**.

<Aside type="note" title="Why 60 meters away">
The distance does not change what an orthographic camera shows, but anything closer to the camera than its **Near** distance (0.05 m), the near plane, is cut away. 60 meters back along a 55 degree tilt puts the camera about 49 meters up, far above the tallest tree you will make.
</Aside>

The template looks like this:

```csharp
using Godot;
using System;

public partial class CameraRig : Node3D
{
	// Called when the node enters the scene tree for the first time.
	public override void _Ready()
	{
	}

	// Called every frame. 'delta' is the elapsed time since the previous frame.
	public override void _Process(double delta)
	{
	}
}
```

Read it from the top:

- `using Godot;` lets the file use Godot's types, such as `Node3D`, without writing `Godot.Node3D` each time. `using System;` does the same for .NET's basic types.
- `public partial class CameraRig : Node3D` declares a [class](/reference/glossary/#class) named `CameraRig`. `: Node3D` means it is a kind of `Node3D`, with everything a `Node3D` can do. `partial` lets Godot add generated code to the class from another file, which it needs for every script.
- Inside the braces after the class name is everything that belongs to the class. `_Ready()` and `_Process()` are **methods**, blocks of code with a name. Godot calls `_Ready()` once when the node enters the game, and `_Process()` every frame. `override` says your method replaces an empty one `Node3D` already has.

### Piece 1: a reference to the camera

The script needs to reach the `Camera3D` to change its size. Change the template so that:

- `using System;`, `_Process()`, and the two comments are gone: the script uses nothing from `System` and needs no work every frame, and the comments only described the template.
- A line `namespace TopDownTemplate.Camera;` sits under `using Godot;`, separated by an empty line. A [namespace](/reference/glossary/#namespace) is a family name for your classes, so your `CameraRig` can never clash with someone else's. Every namespace in the template starts with the project's name, `TopDownTemplate`, followed by the folder under `src` the file sits in, here `Camera`.
- Inside the class, above `_Ready()`, there is a **property**, a named value the class holds, called `Camera` and of type `Camera3D`. Write it `public Camera3D Camera { get; set; }`: `public` lets Godot and other code see it, and `{ get; set; }` means it can be read and changed. Put `[Export]` in front of it, an **attribute**, which is a label in square brackets that tells Godot something about the code after it, and ` = null!;` after it.
- `_Ready()` prints the camera's size with `GD.Print($"Camera size: {Camera.Size}");`.

### Piece 2: zoom

Each time something happens with the keyboard, mouse, or a gamepad, Godot creates an **input event** and offers it to the nodes in the game. A node receives the events nothing else used in its `_UnhandledInput()` method.

Godot compares action names as `StringName`s, a kind of text it can compare very quickly. You keep the two action names in **fields**: plain variables that belong to the class, like a property without the `{ get; set; }`. `Size` is a `float`, a number with a decimal point, and a `float` written in code ends in `f`, as in `1.15f`.

Change the script so that:

- `_Ready()` is gone.
- Two fields at the top of the class hold the action names: `private static readonly StringName ZoomIn = "zoom_in";`, and the same for `ZoomOut` and `"zoom_out"`.
- A new method `public override void _UnhandledInput(InputEvent @event)` checks the event. If `@event.IsActionPressed(ZoomIn)` is true, it divides the camera's size by `1.15f`, with `Camera.Size /= 1.15f;`. Otherwise, if `@event.IsActionPressed(ZoomOut)` is true, it multiplies it by `1.15f`. Write this as `if (...) { ... } else if (...) { ... }`: one event is never both actions, so once the first test matches, `else` skips the second.

<Aside type="note" title="Why StringName fields">
Writing `"zoom_in"` straight into `IsActionPressed` would turn the text into a `StringName` again on every event. `static readonly` makes one `StringName` that the whole class shares and that never changes. `private` keeps it inside the class. ### Piece 3: limits you can tune

Finish the script:

- Add three exported `float` properties with these defaults: `MinSize` `8f`, `MaxSize` `48f`, and `ZoomStep` `1.15f`. 8 meters frames the player and a few steps around it; 48 meters shows a whole small level.
- In `_UnhandledInput()`, use `ZoomStep` instead of `1.15f`, and keep the size between `MinSize` and `MaxSize` with `Mathf.Clamp(value, min, max)`, which returns the value pushed back inside the range. The values you pass in the parentheses are the method's **arguments**: `Camera.Size = Mathf.Clamp(Camera.Size / ZoomStep, MinSize, MaxSize);`, and the same with `*` for zooming out.
- Add three short comments: above the class, saying what it does; above `MinSize` and `MaxSize` together, saying they are the smallest and largest view heights in meters; and above `ZoomStep`, saying how much one wheel notch zooms. `Camera` needs none: its name and type say it all.

## If it does not work

- **The MSBuild panel shows an error such as `CS1002: ; expected`.** The code has a typing mistake on the line it names. `CS` errors come from the C# compiler; the number after them, searched online, explains the error.
- **The Camera row never appears in the Inspector.** The project was not built after you added the property, or the build failed. Click **Build Project** and check the MSBuild panel.
- **The Debugger shows a `NullReferenceException`, and zooming does nothing.** `Camera` is still empty. Assign it in the rig scene, not only in the meadow, and save the rig scene.
- **Godot says it cannot find the script class, or the node has no CameraRig section.** The class name must match the file name exactly: `CameraRig` in `CameraRig.cs`.
- **The wheel does nothing.** The action names in the code must match the input map exactly, `zoom_in` and `zoom_out`, and the wheel events must be on them (lesson 3).
- **The view is gray with no ground.** The rig is not in the meadow, or the camera's **Position z** or the pivot's **Rotation x** are not set. Check the rig scene's values.
- **F5 runs the wrong scene.** The main scene is set in **Project Settings > Application > Run > Main Scene**; set it to `res://levels/meadow.tscn`.
