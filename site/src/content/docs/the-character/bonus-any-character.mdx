## What you will build

Nothing new is modeled. You take a character someone else made, with a skeleton whose bones are called whatever its artist called them, and make it walk with the library from lesson 42. Everything the last lessons built, a BoneMap on the humanoid profile and a fitted animation, is what makes this a few minutes' work.

## What you need

A character model that is **humanoid** (two arms, two legs, a head, an upright body), **rigged** (a skeleton, and a mesh skinned to it), and in **glTF** (`.glb` or `.gltf`). Good free sources:

- **Quaternius** (`https://quaternius.com`): CC0 character packs, many already rigged on a humanoid skeleton. The same artist made the animation library you used, so those characters are the nearest match.
- **Mixamo** (Adobe): thousands of characters and animations, exported as `.fbx`. Godot 4.8 imports FBX itself, but a `.glb` converted in Blender (**File > Import > FBX**, then **File > Export > glTF 2.0**) is the format this course has used throughout.
- A character an artist made for you in Blender: ask for a `.glb`, with the skeleton, in a T-pose or an A-pose.

## The model in this lesson

The lesson uses the **Superhero Male** from Quaternius's **Universal Base Characters** (the free Standard pack, CC0, from `https://quaternius.com`): a realistic, skinned, textured man with hair, eyes, and a 65-bone skeleton with fingers. In the pack, open `Base Characters/Godot - UE` and take `Superhero_Male_FullBody.gltf`, its `.bin` file, and the textures `T_Superhero_Male_Dark.png`, `T_Superhero_Male_Normal.png`, `T_Superhero_Male_Roughness.png`, `T_Hair_1_BaseColor.png`, `T_Eye_Brown.png`, `T_Hair_1_Normal.png`, and `T_Eye_Normal.png`. Put them in one folder, `art/character/superhero`. The `.gltf` is a glTF in several files: the `.bin` holds its geometry and the pictures are the textures, and all must sit beside it.

One snag: the glTF asks for the two normal maps as `T_Hair_1_Normal_png.png` and `T_Eye_Normal_png.png`. If you copy the files under their pack names, Godot cannot find them and reports it in the Output panel. Copy each of those two once more and rename the copy to the name the glTF asks for. The reference project keeps the originals in `art_source/character/superhero`, where Godot does not import them; for this exercise you put the copies in `art`, so Godot can.

## Check the model first

A few minutes before importing saves an afternoon after. Open the file in Blender (or look at it in Godot's Advanced Import Settings preview) and check:

| Check | What you want | If not |
|---|---|---|
| **Scale** | about 1.7 m for an adult | set **Root Scale** on the import |
| **Facing** | faces +Z in Godot, the way your player turns | rotate it in Blender before exporting, or put the model in a `Node3D` turned half a turn |
| **Rest pose** | a T-pose or an A-pose, arms away from the body | the Rest Fixer can mend small differences, a bent rest pose is better fixed in Blender |
| **Skeleton** | one armature, one skin | one skeleton per character, so that the map has one target |
| **Bone count** | any, a body and fingers is fine | bones the profile has no name for stay unmapped |
| **Weights** | at most four bones for a vertex | Limit Total in Blender (lesson 40) |

3. Godot auto-maps. It does not match by name alone: it looks at the **shape** of the skeleton, the chain from the hips up through the spine and neck to the head, and out along each arm and leg, and names each bone for the part of the body it is. That is why it finds `pelvis`, `upperarm_l`, and `thigh_l` as easily as `Hips`, `LeftUpperArm`, and `LeftUpperLeg`.

## Read the map

The reference run reads the map back for this model: **53 of 56** bones are mapped, the same as the animation library. Every bone of the profile has a partner except `LeftEye`, `RightEye`, and `Jaw`, which this skeleton does not have. The map is a long list, since the skeleton has fingers; its main entries are:

| Profile bone | This model's bone |
|---|---|
| `Root` | `root` |
| `Hips` | `pelvis` |
| `Spine`, `Chest`, `UpperChest` | `spine_01`, `spine_02`, `spine_03` |
| `Neck`, `Head` | `neck_01`, `Head` |
| `LeftShoulder`, `LeftUpperArm`, `LeftLowerArm`, `LeftHand` | `clavicle_l`, `upperarm_l`, `lowerarm_l`, `hand_l` |
| `LeftThumbMetacarpal`, `LeftIndexProximal`, ... | `thumb_01_l`, `index_01_l`, ... |

The right side matches the same way. This pack was made by the same artist as the animation library, on the same skeleton, so it maps cleanly; a skeleton from another source may leave a few gaps.

Check yours the same way. On the figure in the map, click each dot and read the bone it names; if a dot is empty, or names the wrong bone, click the **bone field** beside the profile bone's name and pick the right one from the skeleton's list. The usual mistakes are:

- the spine bones off by one, when the model has more spine bones than the profile has (it has `Spine`, `Chest`, and `UpperChest`): set the ones you want by hand and leave the rest unmapped;
- left and right swapped, when a model is built facing the other way: check that `LeftUpperArm` is on the character's left;
- the shoulder bones (`LeftShoulder`) taken for the upper arm, when the model has no shoulder bone: leave `LeftShoulder` empty.

## Reimport and check

<Steps>

1. Click **Reimport**. Godot renames the skeleton's bones to the profile's names, and makes the skeleton unique with the name `GeneralSkeleton`.

2. Choose **Scene > New Inherited Scene...** and pick the model. The scene tree shows the skeleton as `GeneralSkeleton`. The reference run reads its 65 bones: the profile's names for the ones it maps (`Hips`, `Spine`, `Chest`, the arms, the legs, the fingers), and the model's own for the twelve leaf bones the profile has no name for (ten fingertips and two toe tips).

3. Add an **AnimationPlayer** to the root, and load the library into it, as in lesson 42 (**Animation > Manage Animations... > Load Library**). Pick `Walk` and press play.

The rest of the character pipeline is the same as for yours:

Only the numbers change: the stride speed depends on the character's legs.

## Try it

- Break the map on purpose: set `LeftUpperArm` to `lowerarm_l` in the map, reimport, and play the walk. The arm will move wrongly: its clip's rotations land on the wrong bone. Set it back.
- Unmap `LeftToes` and `RightToes`. The feet no longer flex, and everything else is the same.
- Find a model with a skeleton in a T-pose and another in an A-pose, and import both. Compare their arms in the walk. If one looks wrong, turn on **Rest Fixer > Fix Silhouette** in the Retarget options.

## If it does not work

- **The map has no green dots.** The profile is not set. Choose **New SkeletonProfileHumanoid**.
- **The character is tiny or huge.** Set **Root Scale** in the Nodes options of the import.
- **The character walks backward, or on its side.** Its facing is wrong: turn it in Blender before exporting.
- **An arm or a leg bends in the wrong place.** Its bone is mapped to the wrong profile bone. Fix it in the map.
- **The mesh is not skinned.** The model has more than one skeleton, or the mesh is not parented to the armature. Check it in Blender.
- **Godot reports "Auto Mapping couldn't guess" for some bones.** For bones the profile has no name for, it is expected.
