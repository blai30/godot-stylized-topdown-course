## The idea

Right now the meadow's ground is a grid of numbers: `0` is grass, `1` is sand, `2` is dirt. The numbers are the MeshLibrary's item numbers, and nothing in the game knows what they mean. The quick fix is `if (item == 1) speed *= 0.7f;` in the player's script. It works, and it spreads: scattering grass, generating levels, and footstep sounds would each need their own `if (item == 1)`, and renumbering the library would break all of them.

The fix is to keep what a kind of ground means in **data**, in one place. A [custom resource](../../reference/glossary/#custom-resource) is a C# class that extends `Resource`, with [exported](../../reference/glossary/#export) properties. You make one `GroundTile` per kind of ground, and one `GroundTileSet` that lists them. Code asks the set about a tile, and the answer comes from the Inspector.

| Property | What it says |
|---|---|
| `DisplayName` | The name of the ground, for you and for menus. |
| `Item` | The tile's number in the MeshLibrary. This is the only place the number appears. |
| `Layer` | Which layer the tile sits on, from the lowest at 0, as in lesson 17. |
| `GrassDensity` | How thickly grass grows on it, from 0 to 1. Module 6 reads this. |
| `WalkSpeed` | How fast the player walks on it, as a share of normal speed. |

- it has `using Godot;` and the line `namespace TopDownTemplate.Ground;`, with a comment above the class saying it is what one kind of ground means to the game;
- `[GlobalClass]` is on the line above `public partial class GroundTile : Resource`. It registers the class with Godot, so the Inspector can create one from its name;
- it has five exported properties, each with `{ get; set; }`: a `string` `DisplayName` that defaults to `""`; an `int` `Item`; an `int` `Layer`; a `float` `GrassDensity`; and a `float` `WalkSpeed` that defaults to `1f`;
- `GrassDensity` is marked `[Export(PropertyHint.Range, "0,1,0.05")]` and `WalkSpeed` `[Export(PropertyHint.Range, "0,2,0.05")]`, which gives each a slider in the Inspector (minimum, maximum, step);
- `Item`, `Layer`, `GrassDensity`, and `WalkSpeed` each have a short comment above them saying what they are.

## Piece 2: the set

Make a second script the same way, `res://src/Ground/GroundTileSet.cs`, which inherits `Resource` too. Change it so that:

- it has `using Godot;` and `using Godot.Collections;`, the namespace `TopDownTemplate.Ground;`, a comment above the class, and `[GlobalClass]`;
- an exported property `Tiles` of type `Array<GroundTile>` starts as `[]`, an empty list. `Array<T>` is Godot's own list type, and it is the kind Godot can save and show in the Inspector;
- a method `public GroundTile? Find(int item)` loops over `Tiles` with `foreach` and returns the tile whose `Item` equals `item`. After the loop it returns `null`, for an item with no tile. The `?` after the type says the answer can be missing, which the project's `Nullable` setting checks for you.

## Piece 3: ask the ground

The painted ground is the `GroundTiles` GridMap. Give it a script that can say which tile lies under a point.

Open `levels/meadow.tscn`, select `GroundTiles`, and click **Attach Script**. Set **Language** to **C#** (**Inherits** is `GridMap`) and **Path** to `res://src/Ground/GroundMap.cs`, then click **Create**. Change the script so that:

- it has `using Godot;`, the namespace `TopDownTemplate.Ground;`, and a comment above the class: the painted ground, which can say what kind of ground lies at a point;
- an exported `GroundTileSet?` property `Tiles` holds the set. Its type allows `null`, because the Inspector slot is empty until you fill it;
- `public GroundTile? TileAt(Vector3 worldPosition)` first turns the world position into the GridMap's own space: `var local = ToLocal(worldPosition);`, then sets `local.Y = 0f;`, so a point a little above or below the ground still finds the cell, since all the cells are in row 0;
- it reads the item painted there: `var item = GetCellItem(LocalToMap(local));`. `LocalToMap` finds the cell that holds a point, and `GetCellItem` returns the item in a cell, or `InvalidCellItem` for an empty one;
- it returns `null` for `InvalidCellItem`, and otherwise `Tiles?.Find(item)`. The `?.` skips the call when `Tiles` is empty and gives `null`.

## Piece 4: walk by the data

Open `src/Player/PlayerMovement.cs`. Change it so that:

- it has `using TopDownTemplate.Ground;` under `using Godot;`;
- an exported `GroundMap?` property `Ground` sits under `Acceleration`, with a comment: the ground to walk on, which sets how fast each kind of ground lets the player go;
- right after `speed` is picked, a new line multiplies it: `speed *= Ground?.TileAt(GlobalPosition)?.WalkSpeed ?? 1f;`. Read it left to right: if there is a ground, ask for the tile under the player, and if there is a tile, take its walk speed. `??` gives `1f` when any step answered `null`, so the player walks at normal speed off the painted ground.

## Try it

- Select `GroundTiles`, open its **Tiles**, and open the sand tile, element 1. Set its **Walk Speed** to `0.3`, save the meadow, and run again. Nothing in the code changed.
- Invent a fourth kind of ground: add a matching tile to `ground_tiles.tscn` as in lesson 16, export the library, paint it, and add a `GroundTile` with its **Item**. Painted cells with no `GroundTile` make `Find` return `null`, and the player walks at normal speed there.

## If it does not work

- **Walking on sand changes nothing.** Check that `Player` has **Ground** set, that `GroundTiles` has **Tiles** set, and that the sand's **Item** is `1`.
- **The Inspector offers no GroundTileSet under New.** The project has not been built since you wrote the scripts. Click **Build Project**.
- **The MSBuild tab shows a nullable warning about `Find`.** The return type must be `GroundTile?`, with the question mark.
- **The game stops with a NullReferenceException in `Find`.** An element of the set's **Tiles** is still empty. Give each of the three elements a `GroundTile`.
- **The player slows everywhere.** The grass tile's **Walk Speed** is `0`, or two tiles share one **Item**, so the first match wins. Give grass a **Walk Speed** of `1` and every tile its own **Item**.
