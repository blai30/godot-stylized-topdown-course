## The idea

A hand-painted game ground is often a **flat color** multiplied by a [detail texture](/reference/glossary/#detail-texture), a picture in grays. The color says what the ground is: grass green, dirt brown. The detail says how its surface looks: where the blades are, which parts are lit, which are in shadow. A white pixel in the detail leaves the color as it is, a darker one darkens it, so one picture serves any color: you can make the meadow lusher, or autumn, by changing one number, without redrawing anything.

The detail can be drawn by hand in a painting program, as you do for dirt and sand in the next lesson. Grass is different. It needs hundreds of nearly identical shapes, with only their position, direction, and size varied, and no seam where the picture repeats. A script does that well, and it runs the same on every operating system. Most of this ground will be covered by the 3D grass of Module 6, so what shows through is calm, soft in tone, and low in contrast, and a script can hold that evenness better than a hand.

The script draws every blade in a few steps:

1. A blade is a curved shape that is widest near its root and tapers to a point. For each pixel near the blade, the script works out how much of the pixel the blade covers.
2. Blades come in clusters of four to six that fan out from one root, drawn back to front, so each blade overlaps the one behind it, a little lighter.
3. Each blade also darkens the ground a little down and to the right of it, a faint shadow that makes the blades stand out.
4. The picture wraps at its edges: a blade that runs off the right edge continues from the left. That is what makes it tile.

- `public override void _Run()` fills the array with `0.72f`, with `Array.Fill`, and calls `Save()`. A comment says the gaps between the blades start darker than the blades;
- `private void Save()` turns each value into a byte, `(byte)(Math.Clamp(_values[i], 0f, 1f) * 255f)`, in a `byte[]`; makes an image with `Image.CreateFromData(Size, Size, false, Image.Format.L8, bytes)`, where `L8` means one gray byte per pixel; saves it with `image.SavePng(ProjectSettings.GlobalizePath(Path))`, which turns `res://` into a real file path; then calls `EditorInterface.Singleton.GetResourceFilesystem().Scan()`, so the FileSystem dock notices the new file, and prints `Saved` and the path with `GD.Print`.

<Aside type="note" title="Why the picture is a float array">
Painting into an array of numbers and saving once at the end is faster than changing an image pixel by pixel, and it keeps the values as decimals, so the blending in the next pieces does not round away. `Clamp` keeps a value between 0 and 1 before it becomes a byte.
</Aside>

## Piece 2: one blade

Add three small helper methods and one that draws a blade, and draw a single blade in the middle to see it.

Change the script so that:

- `Range(Random random, float low, float high)` is a `private static float` method, used from piece 3 on, returning a random number between `low` and `high`: `low + random.NextSingle() * (high - low)`;
- `Smooth(float low, float high, float x)` is a `private static float` method that eases from 0 to 1 as `x` goes from `low` to `high`, with an S-shaped curve: `var t = Math.Clamp((x - low) / (high - low), 0f, 1f);` and `return t * t * (3f - 2f * t);`;
- `Cover(float dx, float dy, float heading, float length, float width, float bend)` is a `private static` method returning two numbers, `(float Cover, float Tip)`: how much of the pixel the blade covers, 0 to 1, and how far along the blade the pixel is, 0 at the root and 1 at the point. `dx` and `dy` are the pixel's distance from the blade's root. It first turns the pixel's position into blade coordinates: `along`, the distance along the blade's direction, is `dx * MathF.Cos(heading) + dy * MathF.Sin(heading)`, and `across`, the distance to the side, is `dy * MathF.Cos(heading) - dx * MathF.Sin(heading) - bend * along * along / length`; the last term curves the blade. `tip` is `along / length`. A pixel well behind the root or past the point is not covered: when `tip is < -0.1f or >= 1f`, return `(0f, tip)`. `half`, the blade's half width, is `width / 2f * MathF.Pow(Math.Clamp(1f - tip, 0f, 1f), 0.8f) * Smooth(-0.1f, 0.12f, tip)`: full width near the root, shrinking to nothing at the point. `edge` is `1f - MathF.Abs(across) / MathF.Max(half, 1e-6f)`, which is 1 on the blade's middle line and 0 at its side, and the method returns `(Smooth(0f, 0.1f, edge), tip)`: the soft ramp over the last tenth is what makes the edge crisp but not jagged;
- `DrawBlade(float rootX, float rootY, float heading, float length, float width, float bend, float shade)` is a `private void` method. It loops `y` and `x` over the square of pixels within `reach`, `(int)length + 6`, of the root, asks `Cover` about each with `var (cover, tip) = Cover(x + 0.5f - rootX, y + 0.5f - rootY, heading, length, width, bend);`, which unpacks the two numbers it returns, skips pixels where `cover <= 0f`, and finds the pixel's place in the array with `var index = (((y % Size) + Size) % Size) * Size + ((x % Size) + Size) % Size;`. The `%` wraps a position past an edge back to the other side, and the extra `+ Size` keeps a negative position positive; a comment says the picture wraps at its edges, so it tiles. It mixes the blade's gray into the pixel by its cover: `var color = shade * (0.97f + 0.06f * Math.Clamp(tip, 0f, 1f));` makes the tip a little lighter than the root, and `_values[index] = _values[index] * (1f - cover) + color * cover;`;
- `_Run()` calls `DrawBlade(Size / 2f, Size / 2f, -MathF.PI / 2f, 150f, 40f, 0.15f, 0.9f);` after the fill and before `Save()`: a blade at the middle, pointing up the screen (`-MathF.PI / 2f` is straight up, since y grows downward), 150 pixels long and 40 wide.

## Piece 4: tone and shadow

The blades merge because they share one gray. Give each some depth. Change the script so that:

- inside the cluster loop, before the blades, `var tone = Range(random, -0.04f, 0.04f);` is a small difference for the whole cluster: some clusters are a touch lighter, some darker;
- inside the blade loop, `var shade = 0.84f + 2f * tone + 0.05f * order / 5f;` replaces the `0.88f`, with a comment: drawn back to front, each blade a little lighter than the one behind it. `DrawBlade` is given `shade`;
- `DrawBlade` runs its loop twice, `for (var pass = 0; pass < 2; pass++)`, and has `offsetX` and `offsetY` of `4f` and `9f` on pass 0 and `0f` on pass 1, with a comment: pass 0 darkens the gaps a little down and right of the blade, a faint shadow, and pass 1 paints the blade. `Cover` is asked about `x + 0.5f - rootX - offsetX` and `y + 0.5f - rootY - offsetY`. On pass 0 a covered pixel is darkened, `_values[index] *= 1f - 0.07f * cover;`, and on pass 1 it is painted as before.

<Aside type="note" title="Flat, not blurry">
The picture follows three rules. Each blade is **flat**: one tone with only a slight lightening toward its tip. The edges are **crisp**: the soft ramp is only the outer tenth of each side, enough to avoid jagged steps. The **contrast is low**: the lightest and darkest grays are close together. That keeps the ground calm from far away and still readable close up, and the shader can raise or lower the contrast later without a redraw.
</Aside>

<Aside type="note" title="Why it tiles">
A blade near an edge writes to the other side too, because of the `%` in the index. So the right edge of the picture continues into its left edge, and the bottom into the top. Put copies side by side and the blades carry across every seam.
</Aside>

## Import it into Godot

The palette in lesson 11 needed exact colors, so it stayed lossless. This picture is big, repeated everywhere, and seen from afar, so it can use the settings Godot gives most 3D textures.

<Steps>

1. Click `art/ground/grass_detail.png` in the FileSystem dock and click the **Import** tab next to **Scene**.

	<Figure
		src={importBefore}
		alt="The Import dock for grass_detail.png: Import As Texture2D, Compress Mode Lossless, Mipmaps Generate off."
		caption="The defaults: lossless and no mipmaps."
	/>

2. Set **Compress > Mode** to **VRAM Compressed**. Graphics cards can keep this kind of texture compressed in their own memory, VRAM, at a quarter of the size or less. The loss is too small to see on soft, flat shapes.

3. Under **Mipmaps**, check **Generate**. [Mipmaps](/reference/glossary/#mipmap) are the smaller copies Godot draws for ground far from the camera; without them, the blades shimmer as the camera moves.

4. Click **Reimport (\*)**.

	<Figure
		src={importSet}
		alt="The Import dock for grass_detail.png: Compress Mode VRAM Compressed and Mipmaps Generate checked, with the Reimport (*) button below."
		caption="VRAM Compressed with mipmaps, the usual settings for a 3D texture."
	/>

</Steps>

## Try it

- Change the number of clusters from `150` to `80`, build and run the script, and look: a thinner, calmer grass with more of the gaps showing. Set it back to `150`.
- Change the seed in `new Random(404)` to another number and run again: the same kind of grass, arranged differently. The picture is always the same for the same seed.
- Make the blades `Range(random, 60f, 90f)` long and `Range(random, 16f, 22f)` wide, and the clusters `400`, for a finer, shorter lawn, then set them back.
- In Godot, double-click `grass_detail.png` in the FileSystem dock. The Inspector shows the picture and its size, 1024 by 1024.

## If it does not work

- **The File > Run item does nothing, or the Output says the script is not loaded.** The project has not been built since the last change. Click **Build Project**, then run it again.
- **The Output prints a build error.** Compare the line it names with the solution for that piece. A missing `using System;` is the usual cause of `Random` and `Math` errors.
- **The picture is flat gray.** The loop that draws the blades is not called: check that `_Run()` calls `DrawBlade`, or the cluster loop, before `Save()`.
- **The picture shows a blade cut off at the picture's edge, with no continuation on the other side.** The index line is missing its `%` wrapping, or its `+ Size`.
- **The Output shows a save error.** The `art/ground` folder does not exist yet. Make it in the FileSystem dock, and run again.
- **The picture looks different from the figure.** The seed is not `404`, or a number in a piece differs. The solution for each piece is the exact script.
